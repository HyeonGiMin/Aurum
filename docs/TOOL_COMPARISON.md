# Golden vs DataGrip 장단점 분석 — Aurum 은 무엇을 취할 것인가

작성: 2026-08-04

> **근거 표기**
> - Golden 서술 중 메뉴·툴바·로그인 창 구성은 **`Golden6.exe` 를 직접 실행해 확인**한 것이다
>   (GOLDEN_BEHAVIOR.md §6). Golden 8 관련 항목은 배포 바이너리 문자열 추출이 근거다.
> - DataGrip 서술은 제품 일반 지식이며 **이 세션에서 실행해 확인하지 않았다.**
>   실물 검증이 필요한 항목은 그렇게 표시했다.

## 1. 한 줄 요약

| | Golden | DataGrip |
|---|---|---|
| 정체성 | **빠른 단일 DB 쿼리 실행기** | **DB 통합 개발환경(IDE)** |
| 최적 사용자 | 하루 종일 SQL 을 두드리는 운영·개발자 | 여러 DB 를 넘나들며 스키마까지 다루는 개발자 |
| 실패하는 지점 | DB 가 늘거나 스키마 작업이 필요할 때 | 그냥 쿼리 하나 빨리 돌리고 싶을 때 |

## 2. Golden

### 장점

1. **즉시 기동, 가볍다.** 네이티브 Win32. 실행하면 바로 로그온 창이 뜬다.
   무거운 인덱싱·워밍업이 없다.
2. **키보드로 끝난다.** F5/F6/F7/F9/F11/F12, Ctrl+F5·F6(커밋·롤백) 등 손이 기억하는
   키맵. 마우스 없이 실행–확인–커밋이 돈다.
3. **세션 모델이 단순하고 예측 가능.** 창 = 접속 하나, 탭이 그 접속을 공유한다.
   트랜잭션이 어디 걸려 있는지 헷갈릴 여지가 적다(원하면 private 탭).
4. **결과 표현이 실용적.** DataGrid / 고정폭 Text / 실행 Log 를 F12 로 순환.
   Text 보기는 그대로 복사해 메일·이슈에 붙일 수 있다.
5. **그리드에서 바로 편집(EditMode).** ROWID 로 행을 특정해 UPDATE/DELETE/INSERT.
6. **배포가 단순하다.** 설치 파일 하나, 영구 라이선스, 폐쇄망에서도 문제없다.
7. **로그인 항목 관리가 실무적.** 저장된 접속 목록에 Category·AltSchema, 필터,
   Import/Export 까지 있다.

### 단점

1. **Oracle 전용**(6 기준). DB 가 늘면 다른 툴을 또 써야 한다.
2. **스키마를 이해하지 못한다.** 자동완성이 문맥·별칭을 깊게 해석하지 않고,
   없는 테이블·컬럼을 타이핑해도 실행 전엔 모른다.
3. **스키마 작업 도구가 없다.** 비교·동기화·마이그레이션·다이어그램이 전부 없다.
4. **UI 가 구식이고 확장 불가.** 플러그인·스크립팅이 없다.
5. **Windows 전용.**
6. **협업 기능이 없다.** SQL 파일 VCS 연동, 팀 공유 개념이 없다.

## 3. DataGrip

### 장점

1. **멀티 DB 를 하나의 UI 로.** 30종 이상을 같은 화면·같은 키맵으로.
2. **방언을 아는 편집기 — 가장 큰 차별점.** 테이블·컬럼·별칭을 실제로 해석해 완성하고,
   오타를 실행 전에 잡고, **이름 변경 리팩터링이 참조하는 SQL 까지 전파**된다.
   Go to declaration / Find usages 로 SQL 을 코드처럼 탐색한다.
3. **introspection 캐시.** 스키마를 한 번 읽어두고 이후는 캐시로 즉답.
4. **스키마/데이터 비교 + 동기화 스크립트 생성.** 실무에서 DataGrip 을 사는 이유 1순위.
5. **데이터 편집기.** 결과를 고쳐 DML 로 모아 제출, 커밋 전 로컬 변경 미리보기.
6. **입출력이 풍부.** CSV/JSON/XLSX import·export + 스크립트 커스텀 추출기.
7. **ERD, Explain Plan 시각화, 쿼리 히스토리, VCS 연동, 플러그인, 크로스플랫폼.**

### 단점

1. **무겁다.** JVM 기반이라 기동이 느리고 메모리를 많이 쓴다. "쿼리 하나 빨리"엔 과하다.
2. **구독 과금.** 연 단위 비용이 계속 나간다.
3. **학습 곡선.** IntelliJ 개념(데이터 소스·콘솔·스코프)과 키맵에 익숙해져야 한다.
4. **대형 스키마 introspection 비용.** 수천 테이블에서는 최초 읽기·갱신이 부담이다
   *(실물 미검증 — 우리 환경에서 재볼 필요)*.
5. **폐쇄망 운영 부담.** 라이선스 서버·드라이버 다운로드가 걸릴 수 있다 *(실물 미검증)*.
6. **기능이 많아 오조작 여지.** 운영 DB 에서 편집·동기화가 바로 손에 닿는다.

## 4. Aurum 의 자리

**Golden 의 가벼움·키맵·세션 단순함을 유지한 채, DataGrip 의 "스키마를 아는" 부분만
골라 얹는다.** IDE 가 되려 하지 않는다.

### 취한다

| 출처 | 항목 | 상태 |
|---|---|---|
| Golden | 키맵·세션 모델·EditMode·결과 3종 보기·로그인 목록 | ✅ 파리티 완료 |
| Golden | 단일 exe 배포 | ✅ 유지 |
| DataGrip | introspection 캐시 | ✅ 구현됨 (2026-08-04) |
| DataGrip | ERD | ✅ 구현됨 (2026-08-04) |
| DataGrip | Tx 모드·격리 툴바 | ✅ 구현됨 |
| DataGrip | 멀티 DB | 계획 수립됨 (MULTI_DB_PLAN.md) |
| DataGrip | SQL 검증(없는 테이블/컬럼) | 다음 후보 |
| DataGrip | **스키마 비교 + 동기화 DDL** | 최대 미구현 — `iapdb patch` 와 맞물림 |
| DataGrip | Explain Plan 시각화 | 트리는 있음, 비용 막대 미구현 |

### 취하지 않는다 (의도적)

- **플러그인·스크립트 확장** — 스크립트 실행은 보안 검토가 필요하고,
  운영 DB 툴에서 얻는 것보다 잃는 게 크다
- **IDE 급 프로젝트/VCS 통합** — 우리 사용자는 SQL 파일을 이미 다른 도구로 관리한다
- **무거운 인덱싱** — 즉시 기동이 DataGrip 대비 우리의 강점이다

### 우리가 둘 다보다 나아야 하는 것

**PRISMONE 스키마를 안다는 것.** 스키마 버전 pill, 배포 키트 목표 스키마와의 대조,
`iapdb` 와의 연계는 범용 툴이 할 수 없는 영역이다. 스키마 비교의 진짜 가치도
"DataGrip 따라잡기"가 아니라 **운영 DB 가 목표 스키마와 어긋났는지 즉시 보는 것**이다.

## 5. 판단

우선순위는 "둘 다 되는 것"보다 **"우리만 되는 것"** 쪽으로 기운다.

1. 멀티 DB — 없으면 Golden 과의 차별점이 약하다
2. **스키마 비교 + 동기화 DDL** — 배포 키트와 결합하면 DataGrip 보다 유용해진다
3. SQL 검증 — 캐시가 이미 있어 싸다
4. Explain 시각화 — 싸고 체감 있음
